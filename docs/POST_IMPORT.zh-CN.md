# 导入后的处理建议

## Obsidian

建议流程：

1. 保持导出目录结构不变。
2. 直接把导出根目录作为 vault 打开，或者把导出子树复制到现有 vault。
3. 保持每篇笔记旁边的 `*.assets/` 目录不动。

建议：

- 如果 `*.assets/` 目录让文件树太杂，可以用 Obsidian 兼容的文件树插件或视图设置隐藏它们，而不是重命名。
- 在完成 spot check 之前，不要急着启用激进的附件重命名或自动搬移规则。
- 至少抽查几篇大笔记、几篇协作笔记、几篇旧网页剪藏，再考虑删除原始为知数据。

## 思源笔记

建议流程：

1. 先按原目录树导入 Markdown。
2. 第一次导入时，不要修改导出目录名和相对路径。
3. 在校验完成前，把导出目录当作迁移源的事实基线。

建议：

- 不要在导入前把 `*.assets/` 改成 `.assets` 之类的隐藏目录。
- 导入后重点抽查图片渲染、本地文件链接、以及较大的笔记。
- 对 PDF、Office、ZIP、脚本文件等二进制链接要额外留意，这类最容易需要导入侧再调整。

## 通用建议

- 在目标笔记工具校验完成前，保留一份不可变的导出快照作为备份。
- 在目标工具中进行大规模重命名、移动、清理之前，先做笔记级抽样检查。
